# استراتيجية الاختبار وقائمة القبول

> كل اختبار يذكر كود المتطلب الذي يغطيه في اسمه أو تعليقه (SPEC مقدمة). الأدوات: **Pest** (API)، **Vitest + Playwright** (ويب)، **flutter_test + integration_test** (جوال)، **Redocly** (العقد).

---

## 1. الهرم

| المستوى | النطاق | الأداة | متى يُشغَّل | الهدف |
|---|---|---|---|---|
| **وحدة (Unit)** | آلات الحالات، `AccessLevelResolver`، `CandidateRanker`، `ScoringService`، `ReferenceNumber`، التعدادات، النماذج | Pest, flutter_test | كل commit | سريع (< 30 ث)، بلا DB حيث أمكن |
| **ميزة (Feature/API)** | كل نقطة نهاية عبر HTTP مع SQLite in-memory، Policies، Resources، الإشعارات (fake)، الطوابير (sync) | Pest `RefreshDatabase` | كل PR | تغطية كل مسار في `openapi.yaml` |
| **عقد (Contract)** | استجابات الـ API مطابقة لمخططات `openapi.yaml` | Pest + `spectator` (أو `openapi-psr7-validator`) | كل PR | لا انحراف بين الكود والعقد |
| **تكامل (Integration)** | Postgres حقيقي (محفّز عدم التعديل، فهارس جزئية)، MinIO، ClamAV، Redis | Pest على `docker compose` | ليلي + قبل الإصدار | ما لا يحاكيه SQLite |
| **واجهة (Component)** | مكوّنات Vue، RTL، i18n | Vitest + Testing Library | كل PR | — |
| **طرف إلى طرف (E2E)** | الرحلات العشر على بيئة test | Playwright (ويب)، integration_test (جوال P2) | ليلي + قبل الإصدار | الرحلات الحرجة لا تنكسر |
| **أمن** | ASVS الآلي، `composer/npm audit`، Trivy، gitleaks | CI | كل PR / ليلي | SECURITY.md §8 |
| **أداء** | p95 على القراءة، لوحات، تصدير | k6 على test | قبل الإصدار | ARCHITECTURE.md §9 |
| **قبول (UAT)** | القائمة §3 | مختبر المنتج | قبل كل إصدار | توقيع المجلس |

تغطية مستهدفة: Services + Policies + Resources ≥ 90٪؛ الإجمالي ≥ 80٪.

## 2. قائمة الاختبارات الحرجة (يجب أن تمر قبل أي دمج)

### 2.1 عدم تسرّب الحساسية — `tests/Feature/Sensitivity/NoLeakTest.php` (MSG-01, OPP-02, INV-03)

```php
dataset('levels', [AccessLevel::Visitor, AccessLevel::Registered, AccessLevel::ApprovedMember, AccessLevel::Granted, AccessLevel::Connected]);

it('never exposes confidential or sensitive_personal keys below the required level', function (AccessLevel $level) {
    $o = Opportunity::factory()->eligible()->withTeaser()->withDocuments()->create();
    $user = userAt($level, $o);                     // helper يبني المستخدم والمنح/الاهتمام المناسب
    $json = $this->actingAs($user)->getJson("/api/v1/opportunities/{$o->uuid}")->json('data') ?? [];
    $flat = Arr::dot($json);
    foreach (config('sensitivity.opportunity') as $field => $sens) {
        $required = match ($sens) { 'confidential' => AccessLevel::Granted, 'sensitive_personal' => AccessLevel::Connected, 'internal' => null, default => AccessLevel::ApprovedMember };
        if ($sens === 'internal' || ($required && !$level->atLeast($required))) {
            expect(collect($flat)->keys()->filter(fn ($k) => str_contains($k, $field)))->toBeEmpty("{$field} leaked at {$level->value}");
        }
    }
})->with('levels');
```

## 3. قائمة اختبار القبول (UAT) — الرحلات العشر

لمختبر المنتج على بيئة **test** بحسابات البيانات الافتراضية. كل بند: ✓ / ✗ + ملاحظة + لقطة عند الفشل. يُرفق `X-Request-Id` من أدوات المطوّر عند الإبلاغ.

### الرحلة 1 — التسجيل والتحقق (ACC-01, ACC-02)
- [ ] إنشاء حساب مستثمر فرد بالعربية؛ وصول رمزي البريد (Mailpit/بريد الاختبار) والجوال
- [ ] رمز خاطئ 5 مرات → رسالة قفل واضحة بالعربية
- [ ] إعادة إرسال قبل 60 ث → ممنوع مع عدّاد
- [ ] بعد التحقق: اللوحة تعرض «العضوية: مسجّل» ومستوى «مسجّل»
- [ ] تسجيل بالبريد نفسه → رسالة خطأ تحت الحقل
- [ ] تبديل اللغة إلى الإنجليزية (إن كان `features.english=true`) يقلب الاتجاه ويترجم كل النصوص بلا نص عربي متبقٍّ

### الرحلة 2 — الملف الاستثماري والعضوية (ACC-03, ACC-06, ACC-07, INV-01)
- [ ] نسبة الاكتمال تتحرك مع كل قسم محفوظ؛ الحقول الناقصة مسمّاة
- [ ] تقديم العضوية قبل الاكتمال → رسالة تشرح الناقص
- [ ] بعد التقديم: «قيد المراجعة»؛ مسؤول العضوية يراها في `/admin/memberships`
- [ ] مسؤول العضوية يطلب استكمالًا → المستثمر يرى البنود ويعيد التقديم
- [ ] الاعتماد → بريد؛ المستثمر يقبل الشروط → «عضو معتمد»؛ صفحة الفرص تفتح
- [ ] الإيقاف → الفرص تُقفل فورًا مع رسالة السبب

### الرحلة 3 — ملف الفرصة والتقديم (ENT-01..03, ENT-09)
- [ ] صاحب مشروع منشأة ينشئ مسودة؛ الأقسام الخمسة تُحفظ تدريجيًا
- [ ] قائمة الاكتمال تُظهر الحقول والمستندات الناقصة؛ رفع PDF ≤ 25MB ينجح؛ ملف كبير يُرفض برسالة
- [ ] المعاينة «كما يراها المستثمر» لا تُظهر المبلغ الدقيق ولا المستندات ولا بيانات التواصل
- [ ] التقديم بلا إقرار صحة البيانات → ممنوع؛ معه → رقم مرجعي `A-2026-NNNN` + بريد
- [ ] بعد التقديم: الأقسام المقفلة لا تُعدَّل (رسالة واضحة)
- [ ] السحب متاح قبل الربط فقط

### الرحلة 4 — الفرز والاستكمال وSLA (ADM-01..04, ENT-04)
- [ ] المراجع يرى الفرصة «جديدة» في لوحة الإدارة مع موعد المراجعة
- [ ] الإسناد ثم «قيد المراجعة»؛ الخط الزمني يسجّل من/إلى/من فعل/متى
- [ ] طلب استكمال ببندين وموعد → المالك يراهما في «المطلوب منك الآن» (ويب وجوال)
- [ ] المالك يستكمل ويعيد التقديم → «قيد المراجعة» (ليس «جديدة»)
- [ ] تجاوز الموعد → علامة «متأخر» في لوحة الإدارة وتذكير بريدي
- [ ] «غير مؤهلة» بلا سبب → ممنوع؛ بسبب + موافقة مشرف → المالك يرى السبب ويستطيع إعادة التقديم
- [ ] ملاحظة داخلية لا تظهر للمالك في أي شاشة

### الرحلة 5 — التقييم وقرار الأهلية (EVL-01..03)
- [ ] إسناد مقيّم واحد أو ثلاثة → مرفوض؛ اثنان → ينجح
- [ ] المقيّم لا يرى فرصة غير مسندة له
- [ ] محاولة التقييم قبل إقرار تعارض المصالح → ممنوع؛ إقرار تعارض → يُسحب الإسناد
- [ ] نموذج التقييم يعرض المعايير الثلاثة المحاور بوصف السلم 1–5؛ الحفظ كمسودة ثم التقديم
- [ ] شاشة «جنبًا إلى جنب» تُظهر الفروق > 1 ملوّنة
- [ ] قرار «مؤهلة بشروط» مع شروط → تظهر للمالك؛ الحالة لا تتغير إلى «مؤهلة» قبل اعتماد الملخص

### الرحلة 6 — الملخص والترشيح (MAT-01..05)
- [ ] مسؤول الربط يكتب الملخص؛ محاولة إدراج المبلغ الدقيق أو بيانات التواصل → مرفوض
- [ ] اعتماد المجلس ثم موافقة المالك (يرى النص حرفيًا) → الحالة «مؤهلة»
- [ ] تعديل الملخص بعد موافقة المالك → تُلغى موافقته ويُطلب مجددًا
- [ ] قائمة المرشحين مرتبة بدرجة التطابق مع بيان المعايير المطابقة؛ مستثمر بتعارض مصالح غائب
- [ ] الترشيح يتطلب سببًا؛ الحد الأقصى 5؛ المستثمر يتلقى إشعارًا ويرى السبب والمعايير
- [ ] المستثمر يرد «مهتم» → يُنشأ اهتمام تلقائيًا؛ «غير مهتم» بسبب → يُسجَّل

### الرحلة 7 — الاهتمام والموافقة المزدوجة والملف الكامل (INV-02..04, ENT-06, OPP-01..06, DOC-02)
- [ ] المستثمر المعتمد يرى بطاقات الفرص وفق سياسة الوصول (ترشيح فقط افتراضيًا)؛ التصفية والفرز والبحث تعمل بالعربية
- [ ] حفظ الفرصة → تظهر في «المحفوظة» وعدّاد اللوحة
- [ ] التفاصيل: التبويبات الخمسة؛ المستندات «مقفلة»؛ المخاطر «ملخص»
- [ ] إبداء اهتمام بملاحظة → «بانتظار موافقة صاحب المشروع»؛ لا يمكن تكراره
- [ ] المالك يرى طلب وصول **بنوع المستثمر فقط** وبموعد رد؛ يوافق
- [ ] المستثمر: المستندات تطلب NDA؛ القبول → القائمة تظهر؛ التنزيل يعمل والرابط ينتهي بعد 10 دقائق
- [ ] المالك يرى في سجل الوصول من نزّل ومتى (بعد الربط)
- [ ] المجلس يضع «تم الربط» → بيانات تواصل المالك تظهر للمستثمر؛ حالة الفرصة «تم الربط»
- [ ] المستثمر يغلق الاهتمام بسبب → الحالة «مغلق»؛ المستندات تُقفل

### الرحلة 8 — طلبات المعلومات دون كشف الهوية (OPP-05, MSG-01, MSG-02)
- [ ] المستثمر يرسل طلب معلومات → يظهر لدى المجلس باسم المستثمر
- [ ] المجلس يحوّله → المالك يراه **بلا اسم أو بريد**
- [ ] المالك يجيب → المستثمر يرى الإجابة؛ الحالة «تمت الإجابة»
- [ ] المجلس يجيب مباشرة دون تحويل → يعمل أيضًا
- [ ] لا يوجد أي مسار تواصل مباشر بين الطرفين قبل الربط (لا بريد في الواجهة، لا في الإشعارات)

### الرحلة 9 — الاجتماعات (MTG-01, MTG-02)

## 4. بيانات الاختبار

- البذور (SPEC §11) تُنتج: 8 فرص بحالات موزّعة على كامل المسار، 3 مستثمرين (فرد معتمد، مكتب عائلي قيد المراجعة، صندوق بحاجة استكمال)، 3 أصحاب مشاريع، كل أدوار الفريق بحساب لكل دور، معايير التقييم، التصنيفات، الإعدادات، الصفحات القانونية.
- المصانع (factories) تملك حالات مسمّاة: `->eligible()`, `->withTeaser()`, `->connected($investor)`, `->withDocuments()`, `->overdue()`.
- **لا بيانات حقيقية أبدًا** في الاختبارات أو البذور أو اللقطات (SEC-04).
