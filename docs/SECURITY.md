## 2. المصادقة والتحقق بخطوتين

| الضابط | التنفيذ |
|---|---|
| كلمات المرور | bcrypt (cost 12)؛ حد أدنى 8 مع فحص `zxcvbn` في الواجهة؛ رفض كلمات المرور المسرّبة (HIBP k-anonymity، اختياري) |
| التحقق من البريد والجوال | OTP رقمي 6 خانات؛ `otp_codes.code_hash` (sha256 + pepper)؛ صلاحية 10 دقائق؛ 5 محاولات ثم تجميد 15 دقيقة؛ إعادة إرسال كل 60 ثانية |
| الجلسات (ويب) | Sanctum stateful؛ كوكي `HttpOnly; Secure; SameSite=Lax`؛ الجلسة في Redis؛ انتهاء بعد 8 ساعات خمول للفريق، 30 يومًا للمستخدمين |
| الرموز (جوال) | Sanctum PAT مع `device_name`؛ تنتهي بعد 90 يومًا من آخر استخدام؛ إبطال عند تغيير كلمة المرور؛ إدارة الأجهزة في P2 |
| TOTP (ACC-05) | `pragmarx/google2fa-laravel`؛ **إلزامي لكل `staff`** عبر `EnsureTwoFactor` middleware (423 حتى الإكمال)؛ اختياري للبقية؛ 8 رموز استرداد تُعرض مرة واحدة؛ السر مشفّر بـ `APP_KEY` |
| القفل | 5 محاولات دخول فاشلة / 15 دقيقة لكل (بريد + IP)؛ تنبيه بريدي عند القفل |
| استعادة كلمة المرور | رمز موقّع 60 دقيقة؛ رسالة موحّدة لمنع التعداد |
| تغييرات حساسة | تغيير البريد/الجوال يتطلب OTP على الجديد والقديم؛ تعطيل 2FA يتطلب كلمة المرور + رمز |

## 3. التفويض: RBAC + على مستوى السجل

### 3.1 الطبقات

1. **النوع** (`users.type`): يحدّد مجموعة المسارات (`/investor/*`, `/entrepreneur/*`, `/admin/*`).
2. **الدور والصلاحية** (spatie, guard `api`): `Gate::authorize('evaluations.score')` في FormRequest.
3. **السياسة على السجل** (Policy): هل *هذا* المستخدم يرى *هذه* الفرصة؟

```php
// OpportunityPolicy::view
return match (true) {
    $user->hasRole('super_admin', 'matching_officer', 'reviewer') => true,
    $user->hasRole('evaluator')  => $o->evaluationAssignments()->where('evaluator_user_id', $user->id)->exists(), // ACC-04
    $user->hasRole('advisory_member') => $o->advisoryReferrals()->active()->where('advisory_user_id', $user->id)->exists(), // EVL-04
    $user->type->isEntrepreneur() => $o->owner_user_id === $user->id,
    $user->type->isInvestor()     => app(AccessLevelResolver::class)->for($user, $o)->atLeast(AccessLevel::ApprovedMember)
                                     && $o->isVisibleToInvestors(),
    default => false,
};
```

## 4. مستويات الحساسية وتشكيل الموارد

التصنيف (الوثيقة §6.2): **ع** عام · **د** داخلي · **س** سري · **ح** حساس شخصي.

| القاعدة | التطبيق |
|---|---|
| الحقل يحمل تصنيفه في مكان واحد | `config/sensitivity.php` خريطة `model.field → level`؛ تُستخدم في Resources والاختبارات |
| لا يخرج **س**/**ح** إلا بمستوى وصول كافٍ | `OpportunityDetailResource($accessLevel)`؛ `OpportunityFullResource` للمالك والفريق فقط |
| **د** لا يخرج أبدًا لغير الفريق | `internal_notes`, `council_relationship_desc`, `decision_note`, درجات التقييم |
| هوية المستثمر محجوبة عن المالك قبل `connected` | `AccessRequest.investor_type` فقط؛ `InfoRequest` بلا `investor` في مسار المالك |
| الاختبار | `NoLeakTest` يستدعي كل نقطة قراءة بكل مستوى ويؤكّد غياب المفاتيح المصنّفة |
| التقارير | تُجمَّع من DB؛ `reports_viewer` لا يرى صفوفًا فردية |

## 5. أمن المستندات (DOC-01..03)

| المرحلة | الضابط |
|---|---|
| **الرفع** | الحد `documents.max_size_mb` (25)؛ MIME من المحتوى (`finfo`) لا من الامتداد؛ القائمة البيضاء `documents.allowed_mimes`؛ اسم ملف مولَّد (uuid)؛ `sha256` محسوب ومخزّن |
| **الفحص** | `ScanDocumentJob` عبر ClamAV (`clamd` TCP)؛ `scan_result = pending → clean|infected`؛ الملف المصاب يُعزل (bucket quarantine) ويُبلَّغ المالك والفريق؛ **لا يُصدر رابط لملف غير `clean`** (423) |
| **التخزين** | حاوية خاصة (`anonymous none`)؛ SSE-S3/KMS؛ versioning؛ بادئة بالـ uuid لا بالاسم |
| **التنزيل** | `GET /documents/{uuid}/download-url` → رابط موقّع ≤ 10 دقائق، مقيّد بـ `Content-Disposition`؛ يُسجَّل في `document_access_logs` (من، متى، IP، UA) — INV-04 |
| **العلامة المائية (P2)** | `features.watermark` → نسخة PDF مُعلَّمة باسم المستثمر وتاريخ الوصول تُولَّد عند الطلب وتُخبَّأ 24 ساعة |
| **الإصدارات** | `supersedes_document_id`؛ النسخة القديمة تبقى للتدقيق؛ لا حذف فعلي قبل انتهاء الاحتفاظ |
| **الحذف** | soft delete + حذف الكائن بعد فترة الاحتفاظ عبر `privacy:purge` |

| 6 | إقامة البيانات | كل البنية داخل المملكة؛ لا نقل خارجي إلا FCM/APNs بدون بيانات شخصية (PRV-05) | ✓ |

| 8 | الإبلاغ عن الاختراق | إجراء الحوادث §9: إخطار SDAIA خلال 72 ساعة وأصحاب البيانات عند الخطر | ✓ إجراء |
| 9 | سجل أنشطة المعالجة | القالب §6.1 أدناه | ✓ قالب |
| 10 | المعالجون من الباطن | عقود مع مزوّدي SMS/البريد/الاستضافة تتضمن بنود PDPL | ☐ قانوني |
| 11 | مسؤول حماية البيانات | يُعيَّن من المجلس؛ بريده في `platform.official_email` | ☐ إداري |
